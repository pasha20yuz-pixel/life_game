# Game of Life — Conway's Game with Barriers

Игра «Жизнь» Конвея на языке C с графикой на [raylib](https://www.raylib.com/). В игре два режима:

- **Classic** — свободное поле 25×25: рисуешь клетки мышью, запускаешь симуляцию, пробуешь готовые паттерны.
- **Campaign** — 10 уровней с **барьерами** между соседними клетками. Нужно расставить стартовые клетки так, чтобы к целевому поколению в живых осталось не меньше 4 клеток.

Проект выполнен в рамках курсовой работы по оптимизации программ (СПбПУ, 2026).
Авторы: Южалкин П. А., Дубицкий Д. А.

## Быстрый старт

Если Git, компилятор GCC и raylib уже установлены (подробности ниже):

```powershell
git clone https://github.com/pasha20yuz-pixel/life_game.git
cd life_game

$env:PATH = "C:\raylib\lib;$env:PATH"
gcc -std=c99 -D_WIN32_WINNT=0x0601 `
  -I"C:/raylib/include" -L"C:/raylib/lib" `
  src/main_raylib.c src/patterns.c src/file_io.c `
  src/world.c src/barriers.c src/levels.c `
  -lraylib -lopengl32 -lgdi32 -lwinmm -lm `
  -o game.exe

.\game.exe
```

## Что нужно для сборки

Проект проверялся на **Windows** со сборкой через GCC (MinGW-w64). На Linux и macOS сборка не проверялась: команда ниже содержит флаги и библиотеки, специфичные для Windows.

| Компонент | Зачем | Где взять |
|---|---|---|
| GCC (MinGW-w64) с поддержкой C99 | компиляция | [w64devkit](https://github.com/skeeto/w64devkit/releases) или [MSYS2](https://www.msys2.org/) |
| raylib для MinGW | графика, окно, ввод | [релизы raylib](https://github.com/raysan5/raylib/releases) — архив для `win64_mingw-w64` |
| Git (по желанию) | скачивание и работа с репозиторием | [git-scm.com](https://git-scm.com/download/win) |

Команда сборки ниже предполагает, что raylib лежит так:

```
C:\raylib\include   (заголовки, в том числе raylib.h)
C:\raylib\lib       (библиотека libraylib.a / DLL)
```

Если у вас другой путь, замените его в параметрах `-I` и `-L`.

Проверьте, что компилятор найден:

```powershell
gcc --version
```

## Сборка и запуск

Выполняйте команды из **корневой папки проекта** (там, где лежат `src/` и `levels/`).

```powershell
$env:PATH = "C:\raylib\lib;$env:PATH"
gcc -std=c99 -D_WIN32_WINNT=0x0601 `
  -I"C:/raylib/include" -L"C:/raylib/lib" `
  src/main_raylib.c src/patterns.c src/file_io.c `
  src/world.c src/barriers.c src/levels.c `
  -lraylib -lopengl32 -lgdi32 -lwinmm -lm `
  -o game.exe
```

Сборка идёт без флагов оптимизации (то есть как `-O0`). Это сделано намеренно: так проще замерять эффект оптимизаций в курсовой.

Запуск:

```powershell
.\game.exe              # открыть игру
.\game.exe --help       # краткая справка
.\game.exe --version    # версия и авторы
```

Игру нужно запускать **из корня проекта**: уровни читаются из папки `levels/` по относительному пути. Если запустить `game.exe` из другой папки, кампания не загрузит уровни.

## Правила игры

Каждая клетка поля живая или мёртвая. Шаг симуляции идёт по классическим правилам Конвея:

- живая клетка с 2 или 3 живыми соседями остаётся живой, иначе умирает;
- мёртвая клетка ровно с 3 живыми соседями оживает.

Соседи — это 8 клеток вокруг. В кампании добавляется **барьер**: он разрывает связь между двумя клетками, которые соседствуют по стороне. Через барьер клетки не считаются соседями друг друга. Диагональные соседи барьерами не блокируются.

Края поля не замкнуты: клетки за границей считаются мёртвыми.

## Режим кампании

**Цель уровня:** к целевому поколению на поле должно остаться **не менее 4 живых клеток**.

**Ход уровня:**

1. **Расстановка.** Левой кнопкой мыши поставьте стартовые клетки (их количество ограничено, счётчик виден на правой панели).
2. **Симуляция.** Нажмите **Start**. Счётчик поколений показывает прогресс к целевому поколению.
3. **Итог.** Если к целевому поколению осталось 4 и больше клеток, уровень пройден и можно перейти к следующему (**Next Level**). Иначе появляется надпись FAILED, и можно начать заново (**Retry**).

Прогресс сохраняется: при следующем входе в кампанию игра начнёт с последнего открытого уровня.

**Auto Solve** подбирает стартовую расстановку в виде устойчивого блока 2×2: перебирает позиции и проверяет каждую настоящей симуляцией с барьерами. Повторные нажатия предлагают следующую подходящую позицию.

**Про сложность.** Уровни различаются размером поля (от 4×4 до 22×22), числом поколений и расположением барьеров. Они не задумывались как десять тонко сбалансированных головоломок: прежде всего это набор входных данных разного размера для профилирования.

## Формат файла уровня

Уровни лежат в `levels/level1.txt` … `levels/level10.txt`. Вы можете добавлять свои, но число уровней в игре задано в коде (`get_total_levels()` в `src/levels.c`).

```
W H                          ширина и высота поля
MAX_START TARGET_GEN         максимум стартовых клеток; целевое поколение
H строк по (W-1) символов    барьеры между (y,x) и (y,x+1): 1 — барьер есть
H-1 строк по W символов      барьеры между (y,x) и (y+1,x): 1 — барьер есть
описание уровня              одна строка текста
```

Строки с барьерами состоят только из символов `0` и `1`. Файл нужно сохранять в UTF-8 без BOM или в ASCII.

Пример для поля 3×2 (`W=3`, `H=2`) без барьеров, кроме одного между клетками (0,0) и (0,1):

```
3 2
4 5
10
00
000
Level example
```

## Файлы, которые создаёт игра

Рядом с `game.exe` игра создаёт служебные файлы. Они перечислены в `.gitignore` и не попадают в репозиторий.

| Файл | Содержимое |
|---|---|
| `game.log` | журнал событий (старт, переходы между уровнями, победа, поражение) |
| `progress.dat` | номер уровня, с которого начнётся кампания |

Чтобы начать кампанию с первого уровня, удалите `progress.dat`.

## Возможные проблемы

| Симптом | Что делать |
|---|---|
| `gcc` не найден | Установите MinGW-w64 (например, w64devkit) и добавьте его папку `bin` в `PATH`. Перезапустите PowerShell. |
| `raylib.h: No such file or directory` | Проверьте путь в `-I`. В папке должен лежать файл `raylib.h`. |
| `cannot find -lraylib` | Проверьте путь в `-L`. В папке должна лежать библиотека raylib для MinGW. |
| `game.exe` не запускается или сообщает об отсутствующей DLL | Добавьте папку с DLL в `PATH`: `$env:PATH = "C:\raylib\lib;$env:PATH"`. |
| Кампания показывает чёрный экран | Запустите игру из корня проекта и проверьте, что в `levels/` есть файлы уровней. Причину смотрите в `game.log`. |
| В PowerShell не работают многострочные команды | Символ перевода строки в PowerShell — обратный апостроф `` ` ``, и после него не должно быть пробелов. Либо запишите команду в одну строку. |

## Оптимизация (курсовая работа)

Задача курсовой: профилирование, оценка сложности, одна алгоритмическая оптимизация и не менее двух машинно-независимых оптимизаций с замерами после каждого шага.

Планируемые направления (по результатам анализа кода):

- **Алгоритмическая:** ускорение Auto Solve — проверка устойчивости блока 2×2 за O(1) вместо полной симуляции каждой позиции.
- **Машинно-независимые:** отказ от выделения памяти на каждом поколении, развёртывание цикла подсчёта соседей, оптимизация хранения истории ходов.

Окончательный набор будет определён после профилирования. Каждая оптимизация делается отдельным коммитом, поэтому история репозитория отражает порядок работы.
